# 专利查新检索 SKILL

回答一个问题：**这个技术方案拿去申请，审查员可能拿哪几篇文献把它挡下来，授权前景如何**。只就文献论文献——方案自身的撰写质量（26.3 / 26.4 / 33 等文本缺陷）不在本技能范围，见下"范围边界"。

## 定位

| 维度   | 说明                                                             |
| ---- | -------------------------------------------------------------- |
| 时机   | 申请日之前，撰写/申请阶段（也可在立项、立项评审时做）                                    |
| 目的   | 评估新颖性·创造性，判断授权前景；为撰写策略提供依据                                     |
| 起点   | **自己的技术方案**（交底书 / 技术交底材料），已申请但未授权的权利要求                         |
| 检索要求 | **求全**：宁可多检，不留盲区；检索执行时不设公开日上限                                  |
| 产出   | 查新检索报告（含授权前景结论）                                                |
| 服务法条 | 22.2（新颖性）、22.3（创造性）                                            |
| 不涉及  | **撰写质量类缺陷**（26.3 / 26.4 / 33）、**25 条客体**、**9 条重复授权**——见下"范围边界" |

## 范围边界（不做什么）

本技能只回答一个问题：**现有技术里有没有文献挡住这个方案，挡得住几成。** 以下事项不在范围内，不评价、不写论证、不写入报告：

| 排除事项                                             | 为什么排除                                                |
| ------------------------------------------------ | ---------------------------------------------------- |
| **26.3 公开不充分**、**26.4 得不到支持 / 不清楚**、**33 修改超范围** | 这是撰写与审查阶段的问题，取决于权利要求怎么写、说明书怎么支撑，与检索无关；判定要逐段核对说明书与实施例 |
| **25 条客体、5 条违反法律公德**                             | 方案文字即可判断，与检索无关                                       |
| **9 条重复授权**                                      | 需与自有在先申请、同族逐项比对范围，本质是范围比对而非检索                        |
| **FTO / 侵权风险分析**                                 | 那是另一种检索（目标是他人在先权利的范围），检索对象、判断标准、结论口径都不同              |

遇到这些方向时的处理：

1. **只作一句话提示**，例如"另可注意权 1 的支撑问题，本报告未展开"——不写论证、不下结论；
2. 用户明确要求一并评估时，说明**超出本技能范围**，提示另起任务处理，不在本报告内混写；
3. 报告"局限与声明"里写明本报告未评价撰写质量缺陷，避免读者误以为已经排除。

为什么必须切干净：查新结论是给"要不要申请、怎么申请"用的。把撰写问题混进来，读者会分不清哪条有文献支撑、哪条只是格式建议；更实际的是，撰写建议一旦和检索结论混排，客户容易把"这段要改"误读成"这个方案不新"。

## 一、时间界限与证据资格（先定这个）

**查新的时间界限与无效检索不同：检索时不设公开日上限。**

| 类别        | 定义                                              | 用途                 | 检索处理                  |
| --------- | ----------------------------------------------- | ------------------ | --------------------- |
| **现有技术**  | 公开日早于拟申请日（基准日）的公开文献                             | 评价新颖性与创造性          | 不加 `PBD` 上限，检到检索执行日为止 |
| **抵触申请**  | 申请日早于基准日、**公开日不早于**基准日的**中国申请**（含进入中国国家阶段的 PCT） | **仅用于新颖性**，不得用于创造性 | 不设专项检索，命中后按公开时间分类     |
| **非现有技术** | 申请日、公开日均晚于基准日                                   | 不作对比文件             | 与现有技术同样检出，评价阶段剔除、另行提示 |

基准日的确定——**按有无正式申请文件分两种情形**：

1. **尚无正式申请文件**（仅有交底材料、技术方案描述甚至只是一个想法）：此时方案尚未提交，不存在实际申请日，基准日为**拟申请日**；拟申请日未定的，以**检索执行日**为基准日，并在报告中注明"基准日按检索执行日处理，实际申请日推迟会新增现有技术范围"。已有优先权安排（如先在外国提出、再进中国）的，以该优先权日为基准日，且优先权是否成立须核实；
2. **已有正式申请文件**：此时已有**实际申请日**，基准日即**实际申请日**；主张优先权的，以优先权日为基准日，优先权是否成立须逐项核实（首次申请文件是否支持后一申请的权利要求）。

两种情形下均须注意：**部分优先权会带来多个基准日**——方案在优先权文件基础上补充的参数、实施例，补充部分对应的特征不享优先权，其基准日为实际申请日。存在这种情况时，报告要分列两组基准日，不得用一个日期统管。

另需注意：对抵触申请的检索，主要是为了评判**已申请但尚未授权**专利的授权前景——方案一旦提交，这类文献就是后续审查与同主题竞争申请的潜在障碍。

五点容易错的地方：

1. **"能检到"不等于"能用"**：检索范围放到检索执行日，是为了看见全貌；但只有基准日前的文献能作对比文件。报告里要把两类分开列，不能混在一个"对比文件"表里。
2. **抵触申请只限中国申请**。外国申请即使申请日在前、公开日在后，也不构成抵触申请，只能算非现有技术。
3. **抵触申请只能打新颖性**。它不能与现有技术组合评价创造性；并且要求是"**同样的发明创造**"，部分特征重叠不够。
4. **自己的在先申请也构成抵触申请**。同一个技术先申请 A、后申请 B，A 在 B 申请日后公开，A 就是 B 的抵触申请。
5. **拟申请地区不同，抵触申请制度不同**。抵触申请是中国专利法的特有制度；方案若拟申请 EP/US，不要套用该判断，只需把"申请在前、公开在后"的文献列为潜在障碍并注明各国规则差异。

> **宽限期与查新的关系**：24 条宽限期（国家紧急状态、中国政府主办或承认的国际展览会首次展出、规定学术会议首次发表、他人未经同意泄露）是**申请日之后才能主张**的救济。查新阶段方案已公开且落入宽限期的，只能提示"可主张 24 条宽限期，须在申请时声明并附证明"，**不能因此把已公开文献从检索范围中排除**——否则会漏掉真正的障碍文献。

## 二、可评的理由（先确认评什么，再动手检索）

查新报告只评价文献能够否定的理由：

| 理由    | 法条   | 需要的证据                         | 本文件对应位置           |
| ----- | ---- | ----------------------------- | ----------------- |
| 不具新颖性 | 22.2 | 单篇公开全部特征，或抵触申请                | 第 7 步 / `#1–#10`  |
| 不具创造性 | 22.3 | 1篇 + 公知常识或者 2–X 篇组合，结合具有显而易见性 | 第 7 步 / `#11–#18` |

上表就是本技能能处理的全集：**只有需要"找文献、配证据、搭组合"的理由才在这里**。撰写质量问题（26 条各款）不属于检索结论，只在报告局限里声明未评价。

## 三、流程

### 第 1 步 输入确认（A1–A5，一张确认表收完，可跳过）

| #  | 项    | 说明                                                     | 跳过时默认       |
| -- | ---- | ------------------------------------------------------ | ----------- |
| A1 | 输入材料 | 三档：①交底书/方案文件（标准查新）②口述方案（反问补齐后按标准查新）③仅主题词粗查（**降级为预检级**） | 有文件按①；无文件按② |
| A2 | 检索深度 | 完整（约 18–42 条）／快速预检（约 10 条）                             | 完整查新        |
| A3 | 数据库  | 自有账号库优先，无则免费公开库                                        | 有账号用账号库     |
| A4 | 语种   | 默认中英，可按目标市场加德/法/西/日/韩                                  | 中英          |
| A5 | 交付形式 | Markdown（默认）／docx／PDF                                  | Markdown    |

**A1 选③（仅主题词粗查）时自动降级为预检级**：只做第一轮检索、只评新颖性不下创造性结论、报告头注明"预检级"及降级原因。降级是 A1 联动的结果，不再单独询问。

A1 之外，启动前还需确认两件事——不放进确认表，因为它决定整个基准日，必须先问清：

- **技术方案的基准日**：按两种情形问清——①尚无正式申请文件（交底材料/一个想法）：基准日 = 拟申请日，未定则按检索执行日；②已有正式申请文件：基准日 = 实际申请日；主张优先权的按优先权日；
- **拟申请地区**（CN / EP / US / PCT）：影响抵触申请制度是否适用、语种范围、以及创造性高度的地方实践。

### 第 2 步 方案拆解（起点 = 自己的技术方案）

- **背景与问题**：`Q1-Qm`，引交底书原文或申请文件原文，不要替客户改写；
- **技术特征逐项拆解**：`C1-1、C1-2…`（C 前位 = 拟写权项号或已有专利申请权号，后位 = 权项内特征序号）。查新阶段尚无正式权利要求，按**拟写权利要求**编排：独权记 `C1-*`，从权记 `C2-*`、`C3-*`；尚未确定权项布局的，全部特征先记在 `C1-*` 下，待撰写阶段再权项化；
- 每个特征标注：类型（结构 / 步骤 / 参数 / 用途）、对应哪个技术问题、在交底书中的段落依据；
- 识别**发明点**与**常规特征**——检索资源向发明点倾斜，常规特征用宽泛式带过；
- 自造词、企业内部用语必须配通用同义词（**权项用词往往是本案特有的，现有技术不会这么写**，这是查新最典型的漏检成因）。

### 第 3 步 技术方案解释（顺手做，不必单列章节）

查新阶段还没有正式权利要求时，解释的对象是**交底书里的歧义措辞**；查新阶段已有正式权利要求时，解释的对象是**权利要求书的歧义措辞**。通读交底书全文后，对每处可能有两种以上读法的表述（"高温""薄""快速""基本不""适量"等）确定**一个最合理的含义**，作为检索用词与比对基准。

记录：措辞原文 / 确定的含义 / 依据（交底书原文、申请文件原文、实施例、行业惯用含义）/ 对检索词与比对结论的影响。清单随报告第 4 章呈现。

解释口径宽窄会直接改变检索结果的杀伤力：把"高温"解释成 800℃ 以上，可能一篇文献都打不到；解释成 500℃ 以上，可能立刻检到。**口径要选技术上有依据的那一个，不是选对客户有利的那一个**——查新的价值在于提前暴露风险，不是给客户一个好看的数字。

### 第 4 步 检索要素表与分类号（S1 确认后才跑检索式）

- E 表四维度：**技术领域 / 技术问题 / 技术手段 / 技术效果**。同一特征在别人的文献里往往只以"问题"或"效果"的措辞出现，只检手段词必漏；
- 自造词、特殊用语必须配通用同义词；
- 主分类列全 + 相邻分类；降噪写 `NOT`；
- 求全取向：每个**发明点**至少配精确式 + 宽泛式 + 问题导向式三条路径，同义词与近义表达尽量铺开；
- E 表 + 分类号方案交用户确认（S1）后才跑。**快速预检不确认，E 表随报告附录展示。**

详见 [references/search-strategy.md](references/search-strategy.md) §1–§2。

### 第 5 步 按思路铺开检索

全表统一编号 `#1–#18`，先按新颖性思路（找单篇 X 类），再按创造性思路；按语种、从权展开时用子编号（如 `#16-1`）。

查新场景的特有约束：

- **不设公开日上限**——检索范围到检索执行日为止；
- **每条检索式必须对应明确的覆盖目标**（覆盖哪几个特征、给哪条拟写权项用）；
- 申请人定向检索要覆盖**主要竞争对手 + 客户自己及其关联公司**（自己的在先申请同样可能构成抵触申请或障碍）；
- 宁可宽泛式多检、抽样核对，也不要因为怕噪声而漏检——查新的失败模式是漏，不是多。

`#8`（申请人+时间窗）、`#9`（时间窗外延）在查新场景下**同样不设 `PBD` 上限**，用于发现同主题平行申请与文献。

### 第 6 步 补充手段

- **引证追溯**：同类技术的头部企业专利、行业标准文献的引证；引文间同族关系必须标注（同一发明的多份公开文本只算一篇证据）；
- **申请人/发明人追踪**：主要竞争对手、客户自己及其前身、核心发明人名单；
- **非专利文献**：教科书、技术手册、标准、学位论文、会议论文——查新阶段非专利文献的重要性高于无效检索，很多方案的真正障碍是一篇标准或一本手册。

### 第 7 步 证据整理与定级（B1）

文献编号一律 `D1、D2…Dn` 连续编号，"类别"列用 X/Y/A 表达——编号不带类别含义，**改级时按需调整编号与顺序**。

- 一览表：D 编号 / 公开号 / 申请人 / 公开日 / 类别 / 涉及特征 / 一句话要点；
- 定级表（**要点前置**）：D 编号 / 公开号 / 申请人 / 公开日 / **要点** / 类别 / 涉及特征 / 定级理由 / 关键段落号；
- **申请日后公开的文献不入 D 编号表**，单列"风险清单"（公开号 / 申请人 / 公开日 / 与本方案的重叠程度 / 风险说明）；
- 表后写"要点解读"：常规特征（多篇均公开）、命门特征（无一篇完全公开）、组合层数。

### 第 8 步 逐项比对

1. **新颖性**：按**单独对比**原则逐项比对，标准"直接的、毫无疑义地确定"。**以抵触申请主张新颖性的，先按 `comparison-method.md` §3.1 判"同样的发明创造"**——文字不同不等于方案不同，文字相近也不等于方案相同；
2. **创造性：必须评价，不得只评新颖性**。三步法——最接近文献 → 区别特征与**重新确定的**技术问题 → 是否显而易见。每条组合的理由来源落到段落号，**不接受简单并列**；凡主张"属公知常识"的，须附教科书/工具书等书证（书名、版次、页码），无书证只能作辅助论证；
3. **审查员驳回预演**：站在审查员角度，写出"可能以哪几篇、按什么逻辑驳回哪一项拟写权项"，并给出应对（区别特征往哪放、哪些效果数据需补、从权如何布局）。

### 第 9 步 授权前景结论

按**拟写权项逐项**给出 **授权前景：高 / 中 / 低**（"高" = 现有技术难以否定，即授权障碍小），每项须写明：

- 依据的 D 编号与段落号（不能只写"前景中等"）；
- 主要障碍是哪一篇或哪个组合，区别特征在哪里；
- 若被驳回，可往哪个方向修改（限缩到某个从权特征、补充效果数据）。

同时说明**"能不能授权"与"有多大概率授权"是两回事**：前者看文献是否否定新颖性/创造性，后者还取决于审查员对解释的采纳、技术领域实践、撰写质量。两个结论分开写，不要混成一句"前景良好"。

### 第 10 步 结论与输出

按 [references/report-template.md](references/report-template.md) 交付，核心结论包括：

- 是否存在 X 类文献（单篇否定新颖性）；
- 最接近的 2–3 篇文献及与本方案的差异；
- 基准日后公开的同主题文献清单；
- 授权前景逐项结论与撰写建议方向（**只给方向，不代写权利要求**）；
- 检索局限与声明。

## 四、质量红线

1. **检索不设公开日上限**，但**对比文件只能取基准日前的文献**——两类必须分表呈现，混在一起就是事实错误。
2. **创造性必须评价**。只评新颖性的查新报告等于没做——绝大多数申请不是被单篇打死，而是被组合否定。
3. **每条检索式都挂到"覆盖哪些特征、给哪条拟写权项用"**——没有靶点的检索式等于没跑。
4. **基准日先定死，按情形取**：尚无正式申请文件 → 拟申请日（未定则检索执行日）；已有正式申请文件 → 实际申请日；主张优先权 → 优先权日。取哪个、为什么取，写进报告头；有补充内容不享优先权的，分列基准日。
5. **抵触申请不组合**：只能评价新颖性；只限中国申请（含 PCT 进入中国）；须为"同样的发明创造"；自己的在先申请也算。
6. **解释口径单一**：一处歧义只定一个最合理含义，写明依据；不得在检索里用宽口径、在比对里用窄口径。
7. **原文检索失败要有补检**：日/韩/西文改用 `AUTHORITY` 限受理局 + 英文词补检。
8. **单篇优先、组合最短**：能找到 X 类就不要做组合；必须组合时，组合是否有启示论证不可省——"两篇文献都公开了这些特征"不等于"应当结合"。
9. **段落号落到具体位置**，日文用【】并注明以数据库全文为准，正式使用前以官方公报核对。
10. **区分"能不能授权"与"有多大概率授权"**；检索式必须可复现（数据库、字段语法、语种、执行日期、命中数，进附录 B）。

## 五、工具与环境约定

- 数据库：①自有账号库（PatSnap / incoPat 等，语法按库适配）；②免费公开库（Espacenet、Google Patents、CNIPA、PATENTSCOPE）。**报告必须注明实际使用的库**，覆盖差异（全文回溯年限、语义检索能力）写入局限。示例语法以 PatSnap 为主：`TACD/TAC/AN/IN/APD/PBD/AUTHORITY`、`$PARA/$SEN`。
- 非专利文献：教科书、技术手册、国家/行业标准、学位论文、会议论文。查新阶段不可省略——很多方案的真正障碍在这里。
- 取不到全文时：以摘要 + 段落号引用为准，注明"附图未取得、图为据文字自绘"。
- 外文证据：X/Y 类做中文要点翻译，译文按段落号逐段对照，注明"以原文为准"。
- 报告默认对话内 Markdown；选 docx / PDF 时按模板结构转换。
